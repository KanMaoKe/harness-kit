# 能力与边界

harness-kit 为项目准备规则、任务上下文、状态、记忆与技能文件，并提供维护这些文件的命令行工具。默认只生成精简核心，记忆和治理模块按需启用。下表区分程序行为与需要用户、AI 或宿主执行的约定。

## 工具已实现的能力

| 能力 | 实现位置 | 实际行为 |
|---|---|---|
| 项目识别 | `kit/core.py` | 根据项目文件与目录选择模板类型 |
| 初始化 | `kit/init_harness.py` | 生成并预览同一计划：默认精简核心，按需添加 profile 和可选模块，保留已有正文；显式覆盖仅针对项目约定 |
| 标准入口 | `--agents-md` | 可选创建或更新根目录 `AGENTS.md` 的托管片段，保留其他项目指令 |
| Git 归属 | `kit/core.py` / `kit/init_harness.py` | 默认在 `.git/info/exclude` 维护 harness 本地排除规则；`--share-harness` 显式选择共享 |
| 任务存档 | `kit/checkpoint.py` | 在关键节点更新 `STATE.json`；支持 dry-run，完成状态要求验收与验证记录 |
| 任务恢复 | `kit/resume.py` | 校验并读取当前任务状态，输出下一步与优先读取路径 |
| 结构体检 | `kit/doctor.py` | 检查核心文件、项目身份、入口、档案、任务状态、可选记忆、Git 归属与版本 |
| 项目总览 | `kit/status.py` | 扫描指定深度内可识别的子项目并列出问题数 |
| 文件同步 | `kit/sync.py` | 补齐核心与已启用模块缺件并更新版本元数据，不覆盖或迁移已有正文 |
| 本机登记 | `kit/core.py` / `kit/sync.py` | 初始化登记项目路径；`sync --registered` 批量预览与同步，身份冲突时跳过 |
| 可选安装 | `install.py` | 安装代码与技能到指定位置，不注册 hook；卸载可清理旧 hook |

## 模板提供的约定

| 文件 | 目的 | 执行者 |
|---|---|---|
| `PROJECT.md` | 稳定的项目目标、架构与协作约定 | 用户与 AI 填写、维护及遵守 |
| `STATE.json` | 当前任务目标、验收、验证、阻塞及下一步 | 用户或 AI 按阶段更新 |
| `TASKS.md` | 根据任务选择相关上下文与工具 | AI 判断，宿主提供读取和工具能力 |
| `MEMORY.md` | 整理稳定事实与长期决策 | 用户或 AI 蒸馏与更新 |
| `CHECKPOINTS.md` | 记录决策、未完成事项和接续位置 | 用户或 AI 在关键阶段更新 |
| `NARRATIVE.md` | 记录重要转折与决策理由 | 用户或 AI 根据需要整理 |
| 日期日志 | 保存当日工作记录 | 初始化创建当天文件，后续由用户或 AI 维护 |
| `skills/README.md` | 定义技能格式、拆分与验收方式 | 用户或 AI 编写具体技能 |
| 可选治理模块 | `templates/modules/` | 按需生成设计、ADR、Bug、Session、技术债或 Feature 规划模板 | 项目者选择，用户或 AI 维护；不会自动建立流程门禁 |

检查点轮次、按需读取与验收清单属于文本约定，不表示后台自动执行。认知原语是可选的技能组织方法。默认精简档只生成项目规则、任务协作说明和状态；完整档与治理模块均需显式启用，项目入口需要 `--agents-md`。工具不会自动加载这些文件。

## 需要额外接入的能力

- 自动发现并读取项目指令，需要客户端入口或用户明确指定。
- 关键节点主动存档与换客户端后的恢复由 AI 或用户触发；工具不监听对话。
- 每轮上下文注入、工具暴露和执行编排，需要宿主或独立运行时支持。
- 检索可使用宿主提供的文件搜索；本项目没有内置 BM25 或向量库。
- 实际成果验收需要运行项目测试或其他适用检查；文件检查不替代成果验证。
- 运行中的客户端不会仅因文件同步自动重新读取；新会话通过入口或 `resume` 获取最新状态。

当前默认目录、兼容行为、命令参数和安装方式见 [README](../README.md)。
