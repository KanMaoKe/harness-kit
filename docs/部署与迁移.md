这份文档回答三个问题：**东西现在都在哪**、**哪些能挪走**、**怎么挪**。

## 二、迁移判断

### 结论先给

| 组件 | 判断 | 理由 |
|---|---|---|
| **代码、模板、文档** | ✅ **完全可以迁到 E 盘** | hook 命令是绝对路径，指哪读哪，和位置无关 |
| **技能文件** | ⚠️ **必须留在 C 盘**（4 KB） | WorkBuddy 只扫描 `~/.workbuddy/skills/`，这是宿主写死的 |
| **`settings.json`** | ❌ **不能迁** | 宿主启动时固定读这个路径 |
| **`config.json` / `muted.json`** | 建议留 C 盘 | 不到 1 KB，挪走反而增加复杂度 |

**所以最干净的形态是：**

```
E 盘  ← 全部代码、模板、文档（几百 KB，你自己管）
C 盘  ← config.json + muted.json（<2 KB）+ 技能（4 KB）+ settings.json 里十来行 hook
```

C 盘的"不可控部分"从 76 KB 压到 **不到 6 KB**，而且都是文本，一眼能看懂。

## 三、三种安装模式

| 模式 | 命令 | 代码在哪 | 适用 |
|---|---|---|---|
| **就地安装** ★ | `python install.py --in-place` | 就在 clone 目录（你的盘） | 位置可控，推荐 |
| 复制安装 | `python install.py` | `~/.workbuddy/harness-kit/` | 不关心位置 |
| 指定位置 | `python install.py --to "E:/tools/harness-kit"` | 你指定的目录 | 想集中放工具 |

三种模式**都会**：
- 把技能装到 `~/.workbuddy/skills/harness-init/`
- 注册 hook（指向代码实际所在位置）
- 写 config.json

「就地安装」会额外**清理 C 盘遗留的代码**，只留配置。

## 四、迁移步骤（推荐方案）

### 第 1 步：把仓库挪到你自己的固定位置

```bash
# 例：挪到 E:/student/harness-kit
mv "E:/文档/WorkBuddy/2026-10-09-09-27-17/harness-kit" "E:/student/harness-kit"
```

### 第 2 步：就地安装（重新注册 hook，指向新位置）

```bash
cd "E:/student/harness-kit"
python install.py --in-place
```

它会清掉 C 盘那 72 KB 的代码副本，只留 config.json。

### 第 3 步：完全退出并重开 WorkBuddy

hook 配置在启动时快照，**不重启不生效**。

### 第 4 步（可选）：把技能也挪走

如果你连那 4 KB 都不想让它在 C 盘，用目录联接（junction，不需要管理员权限）：

```cmd
rmdir "C:\Users\62378\.workbuddy\skills\harness-init"
mklink /J "C:\Users\62378\.workbuddy\skills\harness-init" "E:\student\harness-kit\skill\harness-init"
```

> ⚠️ 代价：E 盘要是拔了或者路径变了，技能就失效。**不建议**——4 KB 的东西，留着更稳。

## 五、回滚

任何一步都能退：

```bash
# 卸载注册（不删项目里已生成的 .workbuddy/）
python install.py --uninstall

# 或者手动：删掉 settings.json 里 hooks.SessionStart 中带 harness-kit 的那条
# 备份文件都在同级目录：settings.json.bak-<时间戳>
```

## 六、关于「给 WorkBuddy 加个按钮」

**做不到**，说明一下原因：

WorkBuddy 是闭源的桌面应用，我们只能通过它**开放的三条口子**扩展：

| 口子 | 能做什么 | 我们用了吗 |
|---|---|---|
| **hooks** | 在会话生命周期的节点插入脚本 | ✅ 用了 SessionStart |
| **skills** | 让 AI 知道什么时候、怎么调工具 | ✅ 用了 harness-init |
| **连接器 / MCP** | 接入外部服务和数据 | 未用（不需要） |

改界面、加按钮需要改应用源码，做不了。

**但有个等效的东西**：hook 注入提示后，我会弹出一个**带选项的交互卡片**（就像你之前选「1 和 2 有什么区别」那种），效果和「按钮」是一样的——你点一下就行，不用打字。

## 七、关于「让所有项目都用上」

机制是：**你在哪个项目开对话，就会在哪个项目被问一次**。

- 当前配置 `notify_scope: always` —— 所有会话都会问（包括临时工作区）
- 嫌吵可以改回 `project-only`（只对识别为项目的目录问）
- 某个目录不想再被问：`python kit/mute.py --path "<目录>"`
- 想一次铺多个：对每个项目的目录跑一次 `init_harness.py`，或者跟我说「给 XX 建 harness」

**不建议一次给 60 个项目全铺** —— `E:/student/Unity/` 下大部分是练习项目，PROJECT.md 里
「禁止事项」这类内容只有你自己知道，空模板铺上去没有价值，反而变成噪音。
