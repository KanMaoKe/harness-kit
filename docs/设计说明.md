# 设计说明

harness-kit 将跨会话协作需要的信息放进普通项目文件，以命令行维护结构。默认完整档适合需要设计治理、阶段记忆和技能沉淀的复杂项目；精简档为小项目提供核心文件。两档都只是可编辑文件约定与维护工具，不构成自动上下文运行时。

## 文件分层

| 层 | 文件 | 内容 |
|---|---|---|
| 项目规则 | `PROJECT.md` | 目标、架构、命名、开发与验证约定 |
| 任务规则 | `TASKS.md` | 不同任务需要的上下文、工具与流程 |
| 当前任务 | `STATE.json` | 目标、状态、验收、验证、阻塞与下一步 |
| 记忆 | `memory/` | 长期事实、阶段决策、转折与日志 |
| 技能 | `skills/` | 可重复执行的流程及验收方式 |
| 元数据 | `HARNESS.json` | 项目类型、工具版本与生成记录 |

这些文件按用途分开，便于单独修改和按需读取。生成后仍需要结合项目补全；空模板只能提供结构。

## 上下文选择

先确认当前目标，再读取相关文件。稳定规则通常比历史日志优先，近期决策通常比完整历史更适合恢复工作。需要查证时再沿记录中的路径读取原始依据。

任务未知时读取项目摘要并澄清目标，避免因关键词未命中而丢弃工作上下文。工具选择与文件读取规则由 AI 和宿主执行，脚手架不控制模型调用；TASKS.md 的任务分类和上下文选择是协作约定，不是自动注入规则。

## 记忆维护

- 长期记忆保存仍然有效的事实和决策，超出建议长度时整理重复或过时内容。
- 检查点记录关键决策、否决理由、搁置事项与下一步。
- 叙事记录适用于重要转折，不要求每次普通改动都写一篇说明。
- 日期日志保留当日工作证据；阶段摘要应指向可追溯的原始记录。

维护重点是记录当前工作的接续信息，避免同一个事实在多个文件中重复更新。当前任务统一以 `STATE.json` 为摘要，`resume` 提供只读恢复；项目规则模板不再重复保存当前重心和下一步。

## 技能组织

用明确的名称和触发说明描述技能，命中任务后再读取正文与参考资料。技能可以覆盖完整任务，也可以组合小步骤；认知原语只是可选拆分方式。

步骤应说明输入、产出与验收，不要求展示内部思考过程。保留可核查的决策依据、工具结果和验证证据即可。

## 文件保护

初始化默认补缺件、保留已有正文。显式使用 `--force` 才覆盖 `PROJECT.md`，已有任务规则、技能与记忆正文仍保留。同步只补缺件并更新元数据，不自动迁移已有正文。

项目文件默认使用 `.harness/`，运行状态默认使用 `~/.harness-kit/`。代码、状态和宿主目录分别管理，具体兼容行为见 README。

## 接入与提示

命令行无需宿主即可使用。安装技能需明确指定位置，安装器写入实际代码路径。hook 注册与会话提示均需主动启用；提示要求优先处理用户已有的明确任务。

项目指令入口和 hook 协议支持因客户端而异，兼容性需要实际验证。可选 `--agents-md` 维护标准入口片段，默认只生成可手动合并的片段。生成文件不代表客户端已经实际加载。

## 验证边界

体检检查结构与部分文本特征，不能评估项目设计质量或证明任务完成。实际改动仍需运行项目适用的测试，并记录验证结果。

当前限制、公开规范对照与改进优先级见 [项目设计检查](项目设计检查.md)。
